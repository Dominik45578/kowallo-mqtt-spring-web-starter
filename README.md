# kowallo-mqtt-spring-web-starter

A lightweight, high-performance Spring Boot Starter that provides a declarative, Web-MVC-style programming model for handling bidirectional MQTT communication—supporting both inbound message subscription and outbound message publishing via custom annotations. Built explicitly for heavy production loads under Spring Boot 3.5.7 and Java 21.

> [!NOTE]
> After cloning the project, run `mvn clean install` to publish the artifact to your local Maven repository (`~/.m2/repository`).

## Core Architecture & Execution Pipeline

The framework encapsulates the low-level complexities of Spring Integration and Eclipse Paho, transforming binary TCP packet streams into strongly-typed Java objects through a deterministic execution pipeline:

```
[MQTT Broker]
      │ (Binary Payload via TCP Socket)
      ▼
[MqttPahoMessageDrivenChannelAdapter]
      │ (Wraps raw data into org.springframework.messaging.Message<byte[]>)
      ▼
[MessageChannel: mqttInputChannel]
      │ (Pipes Message container to internal subscriber)
      ▼
[MqttMessageDispatcher] 
      │ 1. Extracts 'mqtt_receivedTopic' header
      │ 2. Resolves target bean method via MqttEndpointRegistry using AntPathMatcher
      │ 3. Performs type conversion and Jackson deserialization of byte[] payload
      ▼
[Target Controller Method with @MqttMapping]

```

1. **Ingest & Transport:** The `MqttPahoMessageDrivenChannelAdapter` manages the persistent TCP connection to the broker and subscribes to the configured topic strings.
2. **Spring Messaging Abstraction:** Incoming network packets are converted into `Message<byte[]>` instances. Raw payloads are preserved as byte arrays, while system properties (Topic, QoS, Retained flag) are mapped into `MessageHeaders`.
3. **Routing & Dispatching:** The message is pushed into `mqttInputChannel`, where `MqttMessageDispatcher` intercepts it. The dispatcher checks `MqttEndpointRegistry`, which indexed all `@MqttController` components at application startup.
4. **Reflective Invocation:** Using `AntPathMatcher`, the dispatcher matches the actual topic (e.g., `hardware/device/102/status`) against pattern strings (e.g., `hardware/device/{id}/status`). It resolves method arguments, triggers Jackson deserialization, and executes the method reflectively.

## Annotation Reference

### @MqttController

* **Target:** Type (Class)
* **Purpose:** Stereotype annotation that registers the class as a managed Spring bean (`@Component`). It marks the component for scanning by `MqttEndpointRegistry` to index available message-handling routines.

### @MqttMapping

* **Target:** Method
* **Purpose:** Defines the strict MQTT topic pattern the method handles. Supports standard Ant-style path syntax including wildcards (`*`, ``) and named path segments bounded by curly braces (`{variableName}`).

### @TopicVariable

* **Target:** Parameter
* **Purpose:** Binds a extracted dynamic path segment from the received topic to a method parameter. Automatically converts the string value to the designated method signature type (e.g., `String`, `Long`, `Integer`).

### @MqttPayload

* **Target:** Parameter
* **Purpose:** Instructs `MqttMessageDispatcher` to pass the raw incoming payload through Jackson's `ObjectMapper`, converting the binary JSON format directly into a strongly-typed Java POJO or Record.

### @MqttHeader

* **Target:** Parameter
* **Purpose:** Extracts transport-level metadata from the message header map. Available system properties for MQTT v3/v3.1.1 include:
* `mqtt_receivedTopic` - The exact topic string on which the packet was published.
* `mqtt_receivedQos` - The Quality of Service level utilized (`0`, `1`, `2`).
* `mqtt_duplicate` - Indicates whether this packet is a duplicate delivery transmission.
* `mqtt_retained` - Indicates if the message was delivered from historical broker cache.

> [!WARNING]
> MQTT v5 is currently unsupported.
> Please use MQTT v3.1.1 for production deployments.
---
> [!IMPORTANT]
> MQTT protocol versions `3.0` and `3.1.1` do **not** support native MQTT User Properties / Headers at the protocol level.
> 
> The `@MqttHeader` annotation only exposes metadata internally generated by Spring Integration and Eclipse Paho, such as:
> - `mqtt_receivedTopic`
> - `mqtt_receivedQos`
> - `mqtt_duplicate`
> - `mqtt_retained`
>
> Custom transport-level properties are available only in MQTT v5 environments.

## Configuration Matrix (`spring.mqtt`)

Configure these keys in your `application.yml` or `application.properties` file. All fields undergo strict boot-time validation via Jakarta constraints.

| Property Key | Type | Default Value | Constraints | Description |
| --- | --- | --- | --- | --- |
| `spring.mqtt.enabled` | `boolean` | `true` | None | Toggles the entire MQTT auto-configuration infrastructure. |
| `spring.mqtt.url` | `String` | *None* | `@NotBlank` | Network location of target broker. Must include network transport scheme (e.g., `tcp://localhost:1883`). |
| `spring.mqtt.client-id` | `String` | `spring-mqtt-[UUID_8]` | None | Network client identifier. Defaults to a pseudo-random 8-character string if omitted. |
| `spring.mqtt.topics` | `String[]` | `{"#"}` | `@NotEmpty` | Base network subscription filters. Setting this to `{"#"}` forces a catch-all network route, delegating application-level routing entirely to the internal controller mapping architecture. |
| `spring.mqtt.default-qos` | `int` | `1` | `@Min(0) @Max(2)` | Default Quality of Service mapping strategy applied to low-level subscriptions. |
| `spring.mqtt.username` | `String` | *None* | None | Access credentials for secure broker configurations. |
| `spring.mqtt.password` | `String` | *None* | None | Secret key matching the username string. |
| `spring.mqtt.clean-session` | `boolean` | `true` | None | Controls if state and subscription persistence should outlive connection disruptions. |
| `spring.mqtt.connection-timeout` | `int` | `10` | None | Maximum duration in seconds the network layer blocks while attempting socket connection. |
| `spring.mqtt.keep-alive-interval` | `int` | `60` | None | Transmission cycle time in seconds for background TCP frame keep-alive operations. |
| `spring.mqtt.automatic-reconnect` | `boolean` | `true` | None | Instructs the underlying engine to re-trigger channel construction upon network dropped packets. |

# Technical Implementation Example 
## MqttController

### Configuration (`application.yaml`)

```yaml
spring:
  mqtt:
    enabled: true
    url: tcp://localhost:1883
    client-id: hardware-gateway-primary
    topics:
      - "#"
    default-qos: 1
    username: gateway-service
    password: production-vault-password
    clean-session: false
    connection-timeout: 15
    keep-alive-interval: 30
    automatic-reconnect: true

```

### Data Transfer Object (Record)

```java
package com.kowallo.spring.mqtttest.dto;

public record TelemetryPacketDto(
    String deviceSerial,
    double coreTemperature,
    boolean relayState,
    long epochMillis
) {}

```

### Handler Component (Controller)

```java
package com.kowallo.spring.mqtttest.controller;

import com.kowallo.spring.mqttwebstarter.annotation.MqttController;
import com.kowallo.spring.mqttwebstarter.annotation.MqttMapping;
import com.kowallo.spring.mqttwebstarter.annotation.MqttPayload;
import com.kowallo.spring.mqttwebstarter.annotation.TopicVariable;
import com.kowallo.spring.mqttwebstarter.annotation.MqttHeader;
import com.kowallo.spring.mqtttest.dto.TelemetryPacketDto;

@MqttController
public class PhysicalAssetController {

    @MqttMapping("factory/{facilityId}/device/{rackId}/metrics")
    public void processAssetStream(
            @TopicVariable("facilityId") Integer facilityId,
            @TopicVariable("rackId") String rackId,
            @MqttPayload TelemetryPacketDto telemetry,
            @MqttHeader("mqtt_receivedTopic") String rawTopic,
            @MqttHeader("mqtt_receivedQos") int networkQos) {

        // Business logic execution layer
        System.out.println("Processing pipe for facility: " + facilityId + ", Rack allocation: " + rackId);
        System.out.println("Hardware identification key: " + telemetry.deviceSerial());
        System.out.println("Core thermal index: " + telemetry.coreTemperature() + "C");
        System.out.println("Network ingress context: " + rawTopic + " (QoS level: " + networkQos + ")");
    }
}

```
## Declarative Message Publishing

The framework provides an intuitive, declarative programming model for sending outbound messages. By defining a simple Java interface, you eliminate boilerplate integration configuration, leaving topic construction and data conversion completely to the underlying engine.

### @MqttPublisher

* **Target:** Type (Interface)
* **Purpose:** Identifies the interface as an outbound MQTT bridge. At application startup, the framework generates a dynamic proxy instance using `MqttPublisherRegistrar` and registers it directly into the Spring IoC context. Supports an optional global topic prefix applied to all underlying method routes.

### @MqttPublisherTopic

* **Target:** Method
* **Purpose:** Declares the destination target or dynamic template pattern for message routing. Supports placeholder variables enclosed in curly braces (e.g., `{deviceId}`) which are resolved dynamically at runtime using `@TopicVariable`. You can optionally override the global QoS strategy using the `qos` attribute.

### Technical Publishing Example

#### Publisher Interface Definition

```java
package com.kowallo.spring.mqtttest.publisher;

import com.kowallo.spring.mqttwebstarter.annotation.MqttPublisher;
import com.kowallo.spring.mqttwebstarter.annotation.MqttPublisherTopic;
import com.kowallo.spring.mqttwebstarter.annotation.TopicVariable;
import com.kowallo.spring.mqtttest.dto.TestPayloadDto;

@MqttPublisher("devices/")
public interface SmartLockMqttPublisher {

    /**
     * Publishes telemetry state. The payload object is automatically serialized to JSON.
     */
    @MqttPublisherTopic("{sensorId}/telemetry")
    void sendTelemetry(
            @TopicVariable("sensorId") String sensorId,
            TestPayloadDto payload
    );
}

```

#### Service Implementation

```java
package com.kowallo.spring.mqtttest.service;

import com.kowallo.spring.mqtttest.dto.TestPayloadDto;
import com.kowallo.spring.mqtttest.publisher.SmartLockMqttPublisher;
import org.springframework.stereotype.Service;

@Service
public class DoorLockService {

    private final SmartLockMqttPublisher mqttPublisher;

    public DoorLockService(SmartLockMqttPublisher mqttPublisher) {
        this.mqttPublisher = mqttPublisher;
    }

    public void publishLockState(String sensorId, double currentTemp) {
        TestPayloadDto payload = new TestPayloadDto(sensorId, currentTemp, "ACTIVE");

        // Executes reflective proxy, generates final JSON packet and pushes to the broker
        mqttPublisher.sendTelemetry(sensorId, payload);
    }
}

```
